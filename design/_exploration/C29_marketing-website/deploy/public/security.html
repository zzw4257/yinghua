安全架构 · Whitepaper

映话的安全模型。

100% 本地 · BYOK · 零上传 · 第三方审计可验证。

核心承诺：映话不会收集你的录音、转录内容、AI 总结或 API Key。 本页描述数据如何在你的 Mac 上流动、为什么它不会泄露、以及我们如何让独立审计方验证这一点。

1. 数据流图

下面是从麦克风输入到 AI 总结的完整数据流。所有节点都在本机，只有最后一步会离开你的 Mac。

2. 本地存储

所有用户数据存放在 macOS 标准目录中，由系统级沙盒保护：

  • 录音原始音频：~/Library/Application Support/Yinghua/recordings/（默认 30 天自动清理，可在 设置 → 存储 中调整）
  • 转录文本与索引：~/Library/Application Support/Yinghua/db.sqlite
  • AI 总结：同一 SQLite 数据库，结构化 JSON 存储
  • API Key：macOS Keychain（系统级加密，应用沙盒外进程无法读取）
  • 设置与偏好：~/Library/Preferences/app.yinghua.mac.plist

卸载映话会自动删除上述所有目录与 Keychain 条目。残留文件可通过 设置 → 存储 → 完全清理 一键清空。

3. HTTPS 强制

所有外发网络请求强制使用 HTTPS。映话的 URLSession 在初始化时设置 httpAllowed=NO，任何指向 http:// 的请求会在 socket 层被直接拒绝，不会建立连接。

允许的出站域名（白名单）：

  • api.anthropic.com · BYOK AI 总结（用户主动触发）
  • api.openai.com · BYOK AI 总结（用户主动触发）
  • updates.yinghua.zzw4257.cn · 应用更新检查（每 24 小时 1 次，可关闭）
  • *.icloud.com · iCloud 端到端加密同步（用户主动启用）

所有 BYOK 请求使用 TLS 1.3，证书固定（Certificate Pinning）防止中间人攻击。

4. Sandbox + Hardened Runtime

映话.app 启用 macOS 全部三项运行时保护：

  • App Sandbox：应用只能访问授权目录（Application Support、Documents 中用户授权的部分）。系统级目录（/System、/Library/Apple、/usr 等）全部拒绝访问。
  • Hardened Runtime：禁用 com.apple.security.get-task-allow、com.apple.security.cs.allow-unsigned-executable-memory、com.apple.security.cs.disable-library-validation 等所有调试豁免位。
  • Notarization：每个发布版本都经过 Apple Notarization 服务公证，确保未被第三方篡改。

可执行文件、动态库、Bundle 资源使用 codesign --verify --deep --strict --verbose=2 验证签名链完整。

  • 修复发布前提供致谢（除非你要求匿名）
  • 对真实漏洞报告提供现金奖励：P0 $1,500 / P1 $600 / P2 $200
