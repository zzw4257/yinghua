## 3. 我们收集什么

### 3.1 简明答案

**我们不收集任何数据。**

这一节可以到此为止——但我们理解大多数用户被训练得对"我们不收集任何数据"这种话保持怀疑，所以下面把"不收集"展开成 5 个明确的不做什么，以及我们如何验证这个承诺。

### 3.2 我们不做的 5 件事

我们**不**做以下任何事情：

1. **不运营任何后端服务器**。映话没有 web 后端、没有 API gateway、没有数据库、没有对象存储。开发者无法看到你录制的任何内容，因为我们没有可"看"的地方。
2. **不嵌入分析或追踪 SDK**。映话不集成 Google Analytics、Firebase Analytics、Mixpanel、Amplitude、Sentry、Datadog、任何崩溃上报 SDK 或任何遥测组件。我们在 app 内没有任何代码会向外部服务发起"心跳""指标""事件"上报。
3. **不记录崩溃日志到我们的服务器**。当映话崩溃时，崩溃信息仅在你的 Mac 本地生成（`~/Library/Logs/DiagnosticReports/`），由 macOS 决定是否参与 Apple 的系统级崩溃上报（你可以随时在"系统设置 → 隐私与安全性 → 分析与改进"中关闭）。我们**没有**也**不会**从这些系统日志中读取任何信息。
4. **不在 app 内放置追踪像素、Cookie、指纹脚本或设备指纹采集**。因为映话是原生 macOS app，它没有 webview、没有 web 页面、不支持 JavaScript，所以这些 web 时代的追踪手段根本不适用。
5. **不出售、出租、交换或以任何方式向第三方转让任何用户数据**——因为我们根本没有收集任何用户数据。"我们不卖你的数据"这句话在我们的语境下不是"我们不卖"而是"我们没东西可卖"。

### 3.3 我们如何验证这个承诺

- **应用包内不包含网络遥测代码**：映话的 `Yinghua.entitlements` 仅声明了 `com.apple.security.network.client`（用于 BYOK 总结），但实际网络出口是经过白名单的——只指向用户配置的 AI endpoint（Anthropic / OpenAI / 自定义），不向任何映话自有域名发起请求。
- **App Sandbox + Hardened Runtime 双重保护**：映话在 macOS 沙箱中运行，进程无法写入沙箱外的位置；Hardened Runtime 强制所有外部库经过代码签名验证，进一步防止注入。
- **开源审计路径**：映话的核心客户端是闭源 macOS app，但**网络出口可以通过 macOS 内置的 Little Snitch / 网络监控工具随时审计**。任何外部通信都会以可视化的形式出现在你的网络监控工具中。

## 4. 我们在本地存储什么

虽然我们不在云端收集任何东西，但映话作为一款本地 app，**必须**在 Mac 上存储一些数据才能工作。下面是完整清单，按目录组织。

### 4.1 根目录

映话的所有本地数据存放在：

```
~/Library/Application Support/Yinghua/
```

这是 macOS 标准的 application support 目录，仅在你自己账户下可见，不会被其他用户或系统进程读取。

### 4.2 子目录与文件内容

| 子目录 / 文件 | 存储内容 | 是否含个人数据 | 何时删除 |
|---------------|----------|----------------|----------|
| `recordings/` | 录制的原始音频文件（`.caf` 格式，16kHz mono AAC 压缩）。每个文件命名形如 `rec-2026-08-23T14-32-08.caf` | 是（语音内容） | 30 天后自动清理；用户可在设置中改 retention；卸载 app 时立即删除 |
| `transcripts/` | 转录后的纯文本行（每行包含时间码、说话人标识、文字） | 是（会议内容） | 不自动删除（用户可手动在 Review Mode 删除单条记录）；卸载时删除 |
| `summaries/` | AI 总结的 4 段 JSON（关键瞬间 / 决定 / 待办 / 遗留问题） | 是（会议衍生内容） | 不自动删除；卸载时删除 |
| `settings.json` | 你的非敏感偏好：UI 主题、窗口位置、默认 AI provider、清理策略天数、speech recognition locale | 否（不含可识别个人身份） | 卸载时删除 |
| `keychain/` | **不存任何东西** | n/a | API key 永远存 macOS Keychain，不在此目录 |
| `logs/` | 映话内部诊断日志（不包含音频或转录内容） | 否 | 默认 7 天滚动清理；卸载时删除 |

### 4.3 macOS Keychain（独立的、不在应用沙箱内的位置）

映话的 BYOK API key **不**存放在上述任何目录，而是存放在 **macOS 系统 Keychain** 中，具体条目信息如下：

- **服务名（kSecAttrService）**：`com.yinghua.apikey`
- **条目类型（kSecClass）**：`kSecClassGenericPassword`（通用密码）
- **访问控制（kSecAttrAccessible）**：`kSecAttrAccessibleAfterFirstUnlock`（设备首次解锁后可读，锁屏状态下不读）
- **条目命名约定**：
  - `anthropic.key` / `anthropic.endpoint` / `anthropic.model`
  - `openai.key` / `openai.endpoint` / `openai.model`
  - `custom.key` / `custom.endpoint` / `custom.model`

Keychain 的优势是它的访问由系统级 ACL 控制——即便有人能物理接触到你的 Mac 设备，只要他们不知道你的 macOS 登录密码，就无法读出 API key；而且 Keychain 内容在备份和迁移设备时由 Apple 的加密机制保护。

我们**永远不会**将 API key：
- 写入任何文件（包括 `~/Library/Application Support/Yinghua/` 下的任何位置）
- 上传到任何映话服务器（因为我们没有）
- 通过任何形式的 telemetry 上报
- 包含在崩溃日志或诊断信息中（崩溃日志在捕获时会自动过滤 Keychain 相关字段）

### 4.4 你可以随时查看、修改、删除这些数据

- **查看**：打开 Finder，在菜单栏选择"前往 → 前往文件夹…"输入 `~/Library/Application Support/Yinghua/` 即可看到所有文件
- **修改**：可在映话设置中调整清理策略、删除单条记录；Keychain 条目可用"钥匙串访问"应用查看和删除
- **删除**：卸载映话时 macOS 会自动删除 `~/Library/Application Support/Yinghua/` 整个目录；Keychain 条目需要手动在"钥匙串访问"中删除（卸载时 macOS 不会自动清理第三方 app 写入的 Keychain 条目，这是 Apple 平台设计）

## 5. API Key 是怎么使用的

### 5.1 核心承诺

**你的 API key 永远留在你的 Mac 本地，**不经过映话任何服务器，因为我们没有任何服务器。

### 5.2 技术细节

当你点击"生成 AI 总结"按钮时，映话内部发生以下事情：

1. 从 macOS Keychain（`com.yinghua.apikey` service）读取你预先配置好的 API key——这次读取发生在你的 Mac 上，不经过网络
2. 在内存中构造一个 HTTPS 请求（通过 Apple 的 `URLSession`），目标是：
   - Anthropic 用户：`https://api.anthropic.com/v1/messages`
   - OpenAI 用户：`https://api.openai.com/v1/chat/completions`
   - Custom 用户：你填入的任意 OpenAI 兼容 endpoint URL
3. 在 HTTP Header 中携带 `Authorization: Bearer <your-key>`（OpenAI / Custom）或 `x-api-key: <your-key>`（Anthropic）
4. 请求 body 包含转录文本（不包含原始音频）和一段 system prompt
5. 接收 AI 提供方返回的总结 JSON
6. 将总结保存到本地 `~/Library/Application Support/Yinghua/summaries/`

整个过程**没有第三方中间人**——映话不会作为代理中转你的请求，AI 提供方收到的请求里 `User-Agent` 字段会显示你本地 URLSession 的标识，不会有映话的标识。

### 5.3 我们请求的 AI 提供方收到的内容

| 内容 | 是否发送 | 备注 |
|------|----------|------|
| 你的 API key | 是 | 由你直接发给 AI 提供方；我们不存储 |
| 转录文本 | 是 | 文字，不含原始音频 |
| 时间码 | 是 | `[MM:SS] speaker: text` 格式 |
| 说话人标识 | 是 | 仅为本地 speaker 编号/名字 |
| 原始音频 | **否** | 永远不发送，AI 总结只基于文字 |
| 你的 Apple ID / 邮箱 | **否** | 映话不读取也不发送 |
| 你的设备信息 | **否** | 唯一带过去的 `User-Agent` 是系统 URLSession 默认值 |
| 你的 Mac 序列号 | **否** | 永远不发送 |
| 你的位置 | **否** | 映话不申请也不使用位置权限 |

### 5.4 你的 API key 安全提示

虽然我们尽了最大努力保护你的 key，但你应该意识到：

- 任何 key 一旦交给客户端就存在被恶意软件读取的潜在风险
- 我们建议你在 AI 提供方后台为映话**单独创建一个子 key**（Anthropic Console / OpenAI Dashboard 都支持）
- 给这个子 key 设置合理的**使用上限**（如每月 $20）以防万一
- 定期在 AI 提供方后台审计 key 的调用记录

## 6. 第三方服务

映话本身**不**接入任何第三方服务。但当你使用以下功能时，会与对应的第三方交互。这些交互的隐私实践由第三方各自的隐私政策约束：

### 6.1 Anthropic（当你选择 Anthropic 作为 AI provider 时）

- **用途**：生成会议总结
- **传输内容**：转录文本（不含音频）
- **接收方**：Anthropic PBC
- **隐私政策**：<https://www.anthropic.com/privacy>
- **映话的角色**：映话不参与你与 Anthropic 之间的通信；你的 key 直接交给 Anthropic

### 6.2 OpenAI（当你选择 OpenAI 作为 AI provider 时）

- **用途**：生成会议总结
- **传输内容**：转录文本（不含音频）
- **接收方**：OpenAI, L.L.C.
- **隐私政策**：<https://openai.com/policy/privacy-policy-for-the-openai-api>
- **映话的角色**：同上

### 6.3 Custom OpenAI 兼容 endpoint（当你选择 Custom provider 时）

- **用途**：生成会议总结
- **传输内容**：转录文本（不含音频）
- **接收方**：你在映话设置中填写的任意 endpoint（可能是你自托管的开源模型、公司内部 LLM 网关等）
- **映话的角色**：映话不验证这个 endpoint 是否安全，是否收集数据；你填什么就是什么
- **你的责任**：在填入自定义 endpoint 前，请自行评估该 endpoint 的隐私和安全属性

### 6.4 Apple 平台服务（所有用户）

映话运行在 macOS 上，会调用以下 Apple 系统 API：

- **Speech.framework / SpeechAnalyzer**（macOS 26 引入）：用于本地语音识别
- **AVFoundation / AVAudioEngine**：用于本地音频录制
- **ScreenCaptureKit**（macOS 12.3+）：用于录制系统音频（来自 Zoom / Meet 等会议 app）
- **Security.framework**：用于访问 Keychain
- **UserNotifications**：用于会议结束提醒

这些 API 的行为由 Apple 控制；它们的隐私实践由 Apple 隐私政策覆盖。

### 6.5 macOS 系统级崩溃诊断（所有用户）

当映话崩溃时，macOS 可能生成一份诊断报告并询问你是否愿意提交给 Apple。这个流程完全由 macOS 控制——映话**不会**接收任何崩溃报告。提交崩溃报告的决定权在你，不在我们。

你可以在"系统设置 → 隐私与安全性 → 分析与改进"中：
- 关闭"与 Apple 共享分析数据"
- 删除已与 Apple 共享的现有报告

## 7. 系统权限

映话运行需要以下 macOS 系统权限。**每项权限都需要你显式同意**，且可以随时在"系统设置 → 隐私与安全性"中撤销。

### 7.1 麦克风（NSMicrophoneUsageDescription）

- **用途**：录制会议中你这一方的发言
- **申请时机**：第一次点"开始录制"时
- **撤销后影响**：无法录制本地发言，但 system audio 录制仍可工作
- **系统提示原文**：「映话需要使用麦克风以录制会议中的本地发言。」

### 7.2 屏幕录制（NSScreenCaptureUsageDescription）

- **用途**：录制系统音频（来自 Zoom、Meet、Teams 等会议 app 的远端声音）
- **申请时机**：第一次点"开始录制"时
- **撤销后影响**：无法录制远端发言，只能录你这一方
- **重要提示**：macOS 的"屏幕录制"权限在撤销后需要**重启映话**才能完全生效，这是 Apple 平台的限制
- **系统提示原文**：「映话需要录制系统音频（来自 Zoom、Meet 等会议应用），以便转录与总结。」

### 7.3 语音识别（NSSpeechRecognitionUsageDescription）

- **用途**：将音频转录为文字（macOS 26 的 `SpeechAnalyzer` 或 fallback 到 `SFSpeechRecognizer`）
- **申请时机**：第一次开启实时转录功能时
- **数据流向**：如果使用 `SFSpeechRecognizer`（macOS 较老版本 fallback），Apple 可能会将音频片段发送到 Apple 服务器进行识别；如果使用 `SpeechAnalyzer`（macOS 26+），识别完全在本地完成
- **映话的控制**：映话默认优先使用本地的 `SpeechAnalyzer`；只有在你机器上 macOS 版本低于 26 时才会回退到 `SFSpeechRecognizer`
- **系统提示原文**：「映话需要使用语音识别来实时转录会议内容。」

### 7.4 通知（NSUserNotificationsUsageDescription）

- **用途**：当一场长时间会议结束、总结生成完成时通知你
- **申请时机**：第一次开启相关功能时
- **撤销后影响**：app 内状态正常更新，但不会弹系统通知
- **内容**：通知不包含会议内容文字，仅含"映话：会议总结已生成"这样的中性提示

### 7.5 Apple Events（NSAppleEventsUsageDescription）

- **用途**：自动化控制 Zoom、Meet 等会议 app（如点击"开始录制"时自动让 Zoom 关闭静音）
- **申请时机**：第一次启用该自动化功能时
- **系统提示原文**：「映话使用 Apple Events 自动化控制会议应用。」
- **默认状态**：映话**默认不启用**这个功能，需要你显式开启

### 7.6 我们**不**申请的权限

映话**不**会申请以下权限，因为它们对映话的功能完全不需要：

- **位置**：映话不获取你的地理位置
- **通讯录**：映话不读取你的联系人
- **照片库**：映话不读取你的照片
- **相机**：映话不调用摄像头
- **蓝牙**：映话不使用蓝牙
- **辅助功能**：映话不申请 Accessibility 权限（除非未来版本新增"全局快捷键录制"功能并明确告知）

如果未来某次更新需要新增权限，我们会更新本政策，并在 app 内通过"新增权限"对话框明确告知你。

## 8. 数据保留与删除

### 8.1 音频原文（`.caf` 文件）

- **默认保留期**：30 天
- **到期后行为**：自动删除音频文件
- **保留的产物**：转录文本 + AI 总结继续保留（这才是大部分用户真正想保留的）
- **可配置**：在映话设置 → 通用 → 清理策略中，可改为 7 / 30 / 90 / 180 天，或设为"永不过期"
- **手动删除**：在 Review Mode 中可以单独删除某次会议的完整记录（包括音频 + transcript + summary）

### 8.2 转录文本和总结

- **默认保留期**：永久保留，直到你手动删除或卸载 app
- **自动清理**：不自动清理（这些是文字内容，体积小）
- **手动删除**：单条删除或在 Review Mode 批量删除

### 8.3 API Key

- **保留期**：永久（直到你主动删除或卸载 app）
- **删除方式**：在"钥匙串访问"应用中搜索 `com.yinghua.apikey`，删除所有相关条目

### 8.4 卸载 app 时

当你把映话从 Mac 移除时：

- ✅ `~/Library/Application Support/Yinghua/` 整个目录被删除
- ❌ Keychain 中的 `com.yinghua.apikey` 条目**不会**被自动删除（这是 Apple 平台设计）

我们**建议**在卸载映话前先在"钥匙串访问"中删除 Keychain 条目，以防 API key 残留。

### 8.5 设备丢失或出售时

- **设备丢失**：因为 Keychain 启用了 `AfterFirstUnlock` 保护，且 macOS 启用了 FileVault 全盘加密，他人无法读取你的 API key 和本地数据
- **设备出售前**：建议先在"系统设置 → 通用 → 转移或重置 Mac"中执行"抹掉所有内容和设置"，这会同时清理 Keychain 和本地数据
- **单独清除映话数据**：可以手动删除 `~/Library/Application Support/Yinghua/` 目录 + 清除 Keychain 条目

## 10. GDPR 合规（欧盟用户）

虽然映话不收集任何数据，但为了完整透明，我们仍按 GDPR 要求声明以下事项：

### 10.1 数据控制者（Data Controller）

由于映话不收集任何云端数据，传统的"数据控制者"概念部分不适用。但若按 GDPR 严格定义：

- **本地存储在你 Mac 上的数据**：你本人是数据控制者，我们仅作为数据处理者（且仅在你的设备上，不在我们的服务器上）
- **与 AI 提供方（Anthropic / OpenAI）通信时**：你与 AI 提供方各自为独立的数据控制者；映话不参与其中

### 10.2 数据处理者（Data Processor）

映话作为本地 app 处理你的转录文本和音频以提供核心功能。处理行为**完全发生在你的 Mac 上**，不涉及跨境传输。

### 10.3 跨境传输

**不适用**。你的所有数据不出你的 Mac 设备。只有当你主动使用 AI 总结功能时，转录文本才会被你直接发送给 AI 提供方（Anthropic / OpenAI / 自定义 endpoint）。这次传输由你直接发起，不经过映话任何服务器，跨境传输的合法性由你与 AI 提供方之间的条款决定。

### 10.4 GDPR 赋予你的权利

虽然我们没有云端数据，但我们仍尊重 GDPR 赋予你的权利，并指出**你已经在本地掌控了这一切**：

| GDPR 权利 | 你的实现方式 |
|-----------|--------------|
| **访问权**（Art. 15） | 直接在 Finder 打开 `~/Library/Application Support/Yinghua/` 即可看到所有数据 |
| **更正权**（Art. 16） | 转录文本在 Review Mode 可直接编辑 |
| **删除权**（Art. 17 / "被遗忘权"） | 在 Review Mode 删除单条记录，或直接卸载映话（删除所有本地数据） |
| **限制处理权**（Art. 18） | 卸载映话即停止所有处理 |
| **数据携带权**（Art. 20） | 录制的音频、转录、总结都是开放的 `.caf` / `.txt` / `.json` 格式，可任意复制到其他位置或工具 |
| **反对权**（Art. 21） | 在设置中可关闭所有非必要功能 |
| **不受自动化决策约束权**（Art. 22） | 映话的 AI 总结是人类可读的自然语言，不构成自动化决策 |

### 10.5 数据保护影响评估（DPIA）

由于映话不处理大规模个人数据、不涉及跨境传输、不涉及大规模监控，DPIA 不强制要求。但作为良好实践，我们已评估映话的设计符合 GDPR "data minimization"（数据最小化）和 "privacy by design"（设计即隐私）原则。

### 10.6 监管投诉

如果你认为我们处理你数据的方式有问题（虽然我们不认为存在这种情况），你有权向你所在成员国的数据保护监管机构（DPA）投诉。我们鼓励你先与我们联系以便我们有机会解决问题。

### 10.7 欧盟代表

根据 GDPR Art. 27，若我们处理欧盟居民的数据，需要在欧盟指定一名代表。由于映话**不收集**欧盟居民的数据，我们暂未指定欧盟代表。如未来政策变化我们会更新本节。

## 13. 数据安全

虽然数据全部在本地，我们也采取多层措施保护这些本地数据：

### 13.1 系统级保护

- **App Sandbox**：映话运行在 macOS 沙箱中，无法写入沙箱外的位置
- **Hardened Runtime**：所有外部库经过代码签名验证
- **macOS Keychain ACL**：API key 受系统级访问控制保护
- **Notarization**：映话通过 Apple Notarization 流程分发，确保未被篡改

### 13.2 传输层保护

- 所有到 AI 提供方的请求走 HTTPS（TLS 1.2+）
- 映话不接受自签名证书，强制验证证书链

### 13.3 应用层保护

- 映话不加载远程代码（no remote code loading）
- 不使用 `eval` 或动态代码执行
- 转录文本在 Review Mode 编辑后实时写回磁盘（原子写，不会因崩溃产生半截文件）

### 13.4 用户自助保护建议

- 启用 macOS 的 **FileVault** 全盘加密
- 启用 macOS 的 **防火墙**
- 为你的 macOS 用户账户设置**强密码**（或使用 Touch ID / Apple Watch 解锁）
- 定期检查"系统设置 → 隐私与安全性"中映话的权限设置

### 13.5 我们的承认

没有绝对安全的系统。如果映话或 macOS 平台出现安全漏洞导致你的数据被未授权访问，我们会在 72 小时内通过 support@yinghua.app 邮件列表和映话启动 banner 通知你，并提供缓解建议。
